۱. انتخاب پشته و دلیل آن

این محصول یک لندینگ سئوپذیر با ترافیک پیک، چند فرم چندمرحله‌ای، و یک پنل CRUD با نقش‌هاست؛ نه یک اپلیکیشن سنگین سمت کلاینت. بنابراین معیار انتخاب «کمترین سطح پیچیدگی برای همان خروجی» است.

گزینه مناسب وقتی که حکم برای این پروژه
Livewire 4 تیم Laravel است و UI عمدتاً فرم/جدول/فیلتر است انتخاب اصلی
Inertia + Vue تعامل‌های پیچیده کلاینت، درگ‌اند‌دراپ، حالت آفلاین هزینه اضافه، بدون سود ملموس
React (SPA/API) تیم فرانت جدا و مصرف‌کننده‌های متعدد API فقط اگر بعداً اپ موبایل بخواهی
Blade + Alpine صفحات عمومی با بیشترین سرعت بارگذاری برای خودِ لندینگ
تصمیم معماری: لندینگ /{slug} با Blade رندر سمت سرور (کش‌شونده)، و فقط باکس OTP و فرم ثبت‌نام به‌صورت کامپوننت Livewire. کل پنل مدیریت Livewire. بدون API جدا در فاز اول.

صدور کد بلیط — نقطه بحرانی

کد هر ثبت‌نام {کد بلاگر}-{شماره ترتیبی} است (مثل a10-1). در پیک ثبت‌نام، شمارش بدون قفل حتماً کد تکراری تولید می‌کند. شمارنده روی خود ردیف بلاگر و داخل تراکنش با قفل سطری:

return DB::transaction(function () use ($bloggerId, $data) {
    $b = Blogger::whereKey($bloggerId)->lockForUpdate()->firstOrFail();
    $b->increment('seq');

    return Registration::create([
        ...$data,
        'blogger_id'  => $b->id,
        'seq'         => $b->seq,
        'ticket_code' => "{$b->code}-{$b->seq}",
        'status'      => RegistrationStatus::Pending,
    ]);
});

۳. مسیرها و جریان کاربر

  1. ورود از لینک بلاگر — GET /{slug} با Route Model Binding روی slug و شرط is_active. شناسه بلاگر در session ذخیره می‌شود (اسناد ارجاع تا ۳۰ روز با کوکی امضاشده).
  2. درخواست کد — کامپوننت Livewire شماره را ولیدیت و OTP را در صف ارسال می‌کند.
  3. تأیید کد — پس از تأیید، verified_phone در session و هدایت به فرم.
  4. فرم ثبت‌نام — ولیدیت با FormRequest، سپس صدور کد بلیط اتمیک.
  5. بلیط — صفحه بلیط + دانلود PNG/PDF + پیامک بلیط؛ وضعیت اولیه «در انتظار تماس».
  6. پیگیری — مدیر تماس می‌گیرد، نتیجه را ثبت می‌کند و وضعیت را نهایی می‌کند.
نکته مسیریابی: مسیر /{slug} باید آخرین روت فایل باشد تا با /panel و مسیرهای سیستمی تداخل نکند؛ همچنین یک فهرست کلمات رزرو برای slug نگه دار.

۴. احراز هویت پیامکی (OTP)

  • پروایدر: کاوه‌نگار یا SMS.ir با الگوی پیامکی (Verify Lookup) — تحویل سریع‌تر و بدون فیلترشدن.
  • کد را هش‌شده ذخیره کن (Hash::make)، انقضا ۲ دقیقه، حداکثر ۵ تلاش، پس از مصرف consumed_at.
  • محدودسازی با RateLimiter: حداکثر ۳ ارسال در ۱۰ دقیقه برای هر شماره و هر IP؛ به‌علاوه honeypot روی فرم.
  • ارسال داخل Job با retry و backoff؛ خطای پروایدر نباید تجربه کاربر را قفل کند.

۵. نقش‌ها و دسترسی

دو گارد جدا در config/auth.php: گارد web برای مدیران و گارد blogger برای بلاگرها.

نقش دسترسی
مدیر کل همه بخش‌ها + مدیریت مدیران + حذف بلاگر
مدیر میانی ثبت‌نام‌ها، تماس، پیامک، بلاگرها، گزارش — بدون مدیریت مدیران
بلاگر فقط ثبت‌نام‌ها و آمار خودش؛ بدون تماس، پیامک و تغییر وضعیت

اعمال دسترسی را در لایه کوئری انجام بده، نه در ویو: یک scope مثل Registration::visibleTo($actor) به‌علاوه Policy، تا هیچ صفحه‌ای امکان نشت داده نداشته باشد.

۶. بلیط

  • رندر سمت سرور از یک Blade view با Browsershot (یا spatie/laravel-pdf): خروجی PNG برای پیامک و PDF برای چاپ.
  • QR روی ticket_code با simplesoftwareio/simple-qrcode؛ روز مراسم یک صفحه اسکن ساده برای کنترل ورودی.
  • فایل در storage و دسترسی با URL::temporarySignedRoute — بلیط نباید با حدس‌زدن آدرس قابل دانلود باشد.
  • تولید در صف؛ تا آماده‌شدن، صفحه پیام «در حال صدور نهایی» نشان می‌دهد.

۷. پیامک‌ها و گزارش فعالیت

  • یک SmsService با اینترفیس و درایور به‌ازای پروایدر تا تعویض پروایدر یک خط پیکربندی باشد.
  • قالب‌ها در دیتابیس با متغیرهای {نام} {کد} {تاریخ} {همراه} و رندر با strtr.
  • هر ارسال یک ردیف sms_messages + یک activity_log؛ وضعیت تحویل با webhook پروایدر به‌روز شود.
  • Observer روی Registration برای ثبت خودکار تغییر وضعیت، تا هیچ تغییری بدون ردپا نماند.

۸. ساختار پنل

یک کامپوننت Livewire به ازای هر صفحه، همگی زیر app/Livewire/Panel:

Panel/Registrations       فهرست + فیلتر + صفحه‌بندی + خروجی
Panel/RegistrationShow    پرونده کامل، بلیط، تماس، پیامک، وضعیت
Panel/Bloggers            تعریف، آدرس کوتاه، عکس، فعال/غیرفعال، حذف
Panel/BloggerShow         آمار و ثبت‌نام‌های یک بلاگر
Panel/SmsTemplates        مدیریت قالب‌های پیامک
Panel/Admins              مدیر کل / مدیر میانی
Panel/ActivityLog         گزارش فعالیت با فیلتر و خروجی
  • فیلترها با ویژگی #[Url] تا در آدرس بمانند و قابل اشتراک باشند.
  • صفحه‌بندی با WithPagination (سرور-ساید، نه بارگذاری کل جدول).
  • خروجی Excel/CSV با maatwebsite/excel در صف و ارسال لینک دانلود.

۹. زیرساخت و استقرار

  • سرور داخل ایران (آروان/ابرآراز) برای تأخیر کم و پرداخت/پیامک بومی؛ PHP 8.3، MySQL 8، Redis.
  • صف با Horizon زیر Supervisor؛ همه پیامک‌ها و تولید بلیط روی صف.
  • کش صفحه لندینگ (Response Cache) با بی‌اعتبارسازی هنگام تغییر بلاگر — پیک تبلیغ را همین یک قلم می‌گیرد.
  • بکاپ روزانه با spatie/laravel-backup روی فضای ابری جدا؛ داده ثبت‌نام غیرقابل بازتولید است.
  • مانیتورینگ خطا (Sentry) و لاگ ارسال پیامک؛ هشدار روی افت نرخ تحویل.
